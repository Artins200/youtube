# YouTube Local 1.1 — Android APK и полный проект

- **[APK на GitHub — YouTube-Local.apk](https://github.com/Artins200/youtube/blob/arena/01a0f333-youtube/release/YouTube-Local.apk)** → нажмите **Download raw file**.
- **[Все исходники ZIP](https://github.com/Artins200/youtube/blob/arena/01a0f333-youtube/release/YouTube-Local-Source.zip)**.

Самостоятельное приложение для **Android 7.0+ (API 24+)**: локальные видео, отдельная лента Shorts, офлайн-режим и подключение к настоящему YouTube. Это **не официальное приложение Google**. Аккаунт, подписки, комментарии и загрузки Google не синхронизируются. Импорт файла — сохранение **на устройстве**, а не публикация на YouTube.

## Что изменилось

- Более близкий к YouTube интерфейс: встроенный Roboto, навигация, кнопки, карточки, экран канала, вертикальные сетки и панель действий Shorts, светлая/тёмная темы. На большом экране — сетка видео и боковая навигация.
- **Несколько Shorts за один импорт**. Системный файловый менеджер Android поддерживает множественный выбор. После сохранения есть «Добавить ещё»; защита от повторного нажатия предотвращает дубликаты.
- Тип ролика хранится явно. **Shorts не становятся обычными видео** на главной, в рекомендациях или во вкладке «Видео» канала. В поиске и истории у них собственный вертикальный вид. На главной Shorts остаются отдельной полкой, как в YouTube.
- На странице импорта можно выбрать «Видео»/«Shorts» для каждого файла; новые Shorts — до 3 минут. Для автоматического определения подходят вертикальные и квадратные видео. Тип сохранённого ролика можно изменить через меню ⋮.
- Исправлена высота прокручиваемой ленты Shorts; играет только активный ролик, соседние подготавливаются заранее, дальние освобождаются.
- Ручной и автоматический офлайн-режимы. Настройка сохраняется при перезапуске; при отключённой сети остаются доступны импортированные файлы.
- Онлайн-источники: **официальный плеер/YouTube Data API v3** и **свой HTTPS-сервер Invidious**. Нет выдуманной ленты, встроенных чужих API-ключей и случайных публичных прокси.

## Установка

1. Скачайте APK со страницы GitHub на Android-телефон (кнопка **Download raw file**).
2. Откройте файл и, если Android попросит, разрешите установку из данного источника.
3. В приложении нажмите **+ → Добавить видео / Добавить Shorts → Выбрать файлы**. Можно выбрать несколько файлов. Назовите каждый ролик и нажмите «Сохранить».

**Важно для APK 1.0:** сборка 1.1 подписана **новым тестовым ключом**, поэтому Android не установит её поверх предыдущего APK 1.0. **Не удаляйте старое приложение, пока не сохраните свои файлы:** откройте каждый ролик → «Скачать» и выберите место сохранения. После удаления старого приложения можно установить 1.1 и импортировать эти файлы снова. Локальные комментарии, история и настройки старого приложения при удалении будут потеряны. У этой сборки нет автоматического переноса данных между разными подписями.

Файлы и превью хранятся в IndexedDB Android WebView. Объём ограничен свободным местом и квотой WebView, а воспроизведение — поддерживаемыми устройством кодеками. Для старых устройств нужен обновлённый Android System WebView. Приложение не запрашивает доступ ко всем файлам: используется системный SAF. «Скачать» у локального ролика сохраняет его файл, «Поделиться» открывает системное меню Android.

## Как подключить настоящий YouTube

### Официальный источник

1. **Вы → Настройки → Источник YouTube → Официальный**.
2. Для конкретного видео нажмите **Открыть ссылку YouTube**, вставьте ссылку `https://www.youtube.com/watch?v=…`, `https://youtu.be/…` или `https://www.youtube.com/shorts/…`. **API-ключ для плеера по ссылке не нужен.** Метаданные запрашиваются через официальный oEmbed; если запрос метаданных не проходит, приложение позволяет плееру открыть саму ссылку и показывает ошибку подключения.
3. Для онлайн-поиска и ленты добавьте **свой ключ YouTube Data API v3** из Google Cloud Console. Сервис должен быть включён; настройте ограничения ключа и квоту. Ключ хранится только на устройстве и отправляется Google по HTTPS. Он не входит в APK и не передаётся в iframe плеера.
4. На главной выберите **YouTube**. В поиске также выберите этот источник и нажмите Enter. Запросы идут в `/youtube/v3/search` и `/youtube/v3/videos`, а не в локальный список. Поддерживается переход к следующим результатам. Популярная лента — публичный chart региона US, не персональные рекомендации аккаунта. YouTube Data API не предоставляет надёжный публичный признак Shorts: по одной длительности поиск не переименовывает ролики в Shorts. Ссылки `/shorts/` и явная метка выбранного сервера сохраняют отдельный формат просмотра.

Используется официальный встроенный плеер YouTube; автор может запретить встроенный просмотр. При ошибке есть кнопка открытия во внешнем YouTube/браузере. Официальный плеер требует действительного HTTPS-origin/referrer и доступа к доменам YouTube. Ошибки источника не выдаются за успешный просмотр.

### Свой Invidious-сервер

1. **Настройки → Свой сервер Invidious → Адрес HTTPS-сервера**.
2. Укажите адрес **уже работающего собственного или доверенного сервера** с API Invidious. В проекте не развёрнут постоянный публичный сервер и не зашит адрес неизвестного оператора. Документация: [Invidious API](https://docs.invidious.io/api/), [самостоятельное размещение](https://docs.invidious.io/installation/).
3. Включите **Видеопотоки через сервер**. Приложение запрашивает `local=true`, использует проксируемый поток или встроенный плеер выбранного сервера с `local=true`. В APK в этом режиме дополнительно запрещены прямые запросы видеопотоков к `*.googlevideo.com`. Сервер должен действительно поддерживать выдачу видео через себя; приложение не делает скрытого автоматического перехода к прямым потокам.
4. В браузерной/PWA-версии API сервера должен разрешать CORS для origin приложения. В Android используется ограниченный нативный HTTPS-клиент для API-запросов.

**Отсутствие блокировок РКН не гарантируется.** Доступ зависит от вашей сети, самого источника и его оператора. Для альтернативного пути нужен доступный сервер или настроенная доступная сеть; поле «сервер» само по себе не создаёт сервер и не устраняет блокировку. Поиск и просмотр через Invidious видны его оператору. Используйте доверенный источник.

## Офлайн-режим

**Вы → Настройки → Офлайн-режим**:

- отключает онлайн-запросы и внешние превью/плееры;
- показывает только импортированные файлы на главной, даже если ранее выбран YouTube;
- не удаляет видео и не сбрасывает выбранный онлайн-источник;
- не скачивает YouTube-видео и **не обходит блокировки**.

«Автоматически без интернета» реагирует на потерю/восстановление подключения. На Android используется состояние сети ОС. Ошибка отдельного сервера при наличии подключения отображается отдельно: наличие сети не означает доступность YouTube.

Сохранение онлайн-ссылки в «Смотреть позже» **не сохраняет видеофайл**. Для офлайн-просмотра импортируйте собственный файл. В APK интерфейс всегда находится внутри пакета; в PWA сначала нужно открыть приложение с сетью и дождаться кэширования оболочки. В service worker кэшируются только статические ресурсы, не API-ответы, ключи или видеопотоки.

## Проект

- `app/index.html`, `app/styles.css`, `app/app.js` — интерфейс, импорт нескольких файлов, локальный плеер, Shorts и настройки.
- `app/media.js` — классификация роликов и безопасный разбор ссылок.
- `app/db.js` — IndexedDB; запись подтверждается **после завершения транзакции**.
- `app/youtube.js` — реальные API-адаптеры, отмена запросов, таймауты, метаданные, поиск и плеер.
- `app/native.js` — адаптер нативных вызовов. Каждый Java-метод требует случайный токен, доступный только доверенной основной странице, а не внешним iframe.
- `app/sw.js`, `app/fonts/`, `app/icons/` — офлайн-оболочка и встроенные ресурсы. Roboto распространяется по SIL OFL 1.1; лицензия включена.
- `android/app/src/main/java/app/ytlocal/player/` — Android WebView, множественный SAF-выбор, fullscreen/Back, сохранение/обмен файлами, мониторинг сети и ограниченный HTTPS-клиент.
- `tools/build-apk.sh`, `tools/sign-apk.mjs` — настоящая сборка и подпись APK без Gradle.
- `tests/` — регрессии базы, типов, ссылок, сетевых адаптеров и интерфейса. Цветные WebM-файлы в `tests/fixtures/` — маленькие тестовые клипы, **не входят в APK**.

Android package: `app.ytlocal.player`; versionCode `2`, versionName `1.1.0`; minSdk 24, target/compileSdk 33. Разрешения: `INTERNET`, `ACCESS_NETWORK_STATE`; общих разрешений чтения/записи хранилища нет. HTTPS-проверка сертификатов не отключается, cleartext HTTP запрещён.

### Сборка

**Android Studio:** откройте `android/`, установите SDK Platform 33 и JDK 17, соберите **Build → Build APK(s)**. Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Веб-ресурсы автоматически копируются из `app/`. Gradle использует собственный debug-ключ: он не совпадает с подписью опубликованного APK.

**Без Gradle**, с JDK 17, Android SDK Platform 33 и Android Build Tools:

```bash
export JAVA_HOME=/путь/к/jdk17
export ANDROID_HOME=/путь/к/android-sdk
./tools/build-apk.sh
# release/YouTube-Local.apk
```

Если Build Tools не содержит `apksigner`, выполните `npm ci --prefix tools`: доступен резервный подписыватель v1/v2/v3. Скрипт сохраняет тестовый ключ **вне репозитория**, в `$HOME/.apk-signing/youtube-local/`, и использует его при следующих сборках. Можно задать `APK_SIGN_DIR` либо `APK_KEY`/`APK_CERT` (PEM). Сохраните свой ключ отдельно; **не публикуйте приватные ключи в Git или ZIP исходников**. Готовый APK заменяется только после успешной подписи и проверки выравнивания.

```bash
apksigner verify --verbose release/YouTube-Local.apk
zipalign -c 4 release/YouTube-Local.apk
sha256sum -c release/SHA256SUMS
```

### Браузер и тесты

```bash
python3 app/serve.py 8080
# http://localhost:8080; сервер также доступен на 0.0.0.0:8080

npm ci --prefix tools
npm test --prefix tools
npx --prefix tools playwright install chromium
# При работающем сервере выше:
npm run test:browser --prefix tools
```

Для внешнего тестового браузера можно задать `CHROMIUM_EXECUTABLE`; для другого адреса приложения — `TEST_URL`. Снимки интерфейса пишутся в игнорируемый каталог `test-artifacts/`.

Выполнены unit-тесты, браузерные проверки пакетного импорта/свайпов/разделения Shorts, ручного и автоофлайна, сохранения данных и воспроизведения при полностью отключённой сети. Онлайн API в регрессиях **замоканы**: это проверка адаптеров, не доказательство доступности живых серверов или обхода РКН. APK собран, подписи v2/v3, ZIP/DEX и выравнивание проверены. **На физическом Android-устройстве эта сборка не запускалась.**
